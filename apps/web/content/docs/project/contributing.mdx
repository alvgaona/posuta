This page is for working on posuta itself, not on a poster. It covers how the repository is laid
out, the commands you run, the commit rules, and how a release is made.

Before you change behaviour, read the
[agreed decisions in AGENTS.md](https://github.com/alvgaona/posuta/blob/main/AGENTS.md), which
include static output only, MDX authoring, Plot and KaTeX at build time, tools before
components, and components without styling. Change them only after discussing it.

## Repository layout

The repository is a [pnpm workspace](https://pnpm.io/workspaces), which means several
packages in one repository, installed together.

- **`packages/posuta`** (published as `@posuta/posuta`) holds the Astro integration, the components, `base.css`, the tools
  (`@posuta/posuta/plot`, `@posuta/posuta/tex`, `@posuta/posuta/print` and the rest) and the `posuta` command line
  (`posuta pdf`, `posuta install`). Its tests are in `packages/posuta/test`.
- **`packages/create-posuta`** is the scaffolder behind `pnpm create posuta`. When the package is
  packed for publishing, it bundles a copy of `template/`, but inside the repository it reads
  `template/` directly.
- **`template`** is the starter poster that `create-posuta` copies, and what `pnpm dev` runs.
- **`apps/web`** is this documentation site (Fumadocs on Astro). Pages are MDX files in
  `apps/web/content/docs/`.

## Commands

Run these from the repository root after `pnpm install`.

| Command | What it does |
| --- | --- |
| `pnpm dev` | Runs the template poster at `http://localhost:4321`. |
| `pnpm build` | Builds the template into `template/dist`. |
| `pnpm pdf` | Builds the template, then exports `template/dist/poster.pdf` and `handout.pdf`. |
| `pnpm test` | Runs every package's tests. |
| `pnpm docs` | Runs this documentation site. |
| `pnpm docs:build` | Builds this documentation site. |

The PDF export and some tests need Playwright's Chromium. Install it once.

```sh title="Terminal"
pnpm --filter posuta-template exec posuta install
```

## Commit messages

Commits follow [Conventional Commits](https://www.conventionalcommits.org). Each message starts
with a type, a scope in parentheses, a colon and the subject.

```text title="Terminal"
feat(posuta): print scale, a factor on the printed type size
fix(posuta): live charts print their build-time drawing
```

[commitlint](https://commitlint.js.org) checks every message with the conventional preset
(`commitlint.config.mjs`). The subject may start with a capital letter, since subjects often
begin with a proper noun. [lefthook](https://lefthook.dev) installs a `commit-msg` hook during
`pnpm install` (`lefthook.yml`), so a bad message is rejected when you commit.

## Continuous integration

`.github/workflows/ci.yaml` runs on every push to `main` and on every pull request. It has three
jobs.

- **commitlint** checks the messages of the commits in the push or pull request.
- **build** installs Playwright's Chromium, builds the template, runs `pnpm test`, exports the
  template to PDF and uploads `poster.pdf` as an artifact of the run.
- **docs** builds the documentation site.

## Releases

`@posuta/posuta` and `create-posuta` are released together, at the same version. A new poster depends on
`@posuta/posuta` at `create-posuta`'s version, so the two must match.

1. Set the same version in `packages/posuta/package.json` and
   `packages/create-posuta/package.json`, and commit.
2. Push a tag named after it, with a `v` in front.

   ```sh title="Terminal"
   git tag v0.2.0
   git push origin v0.2.0
   ```

Then `.github/workflows/release.yaml` runs these steps.

1. Fails unless both packages' versions equal the tag.
2. Runs the tests.
3. Writes the release notes from the commits since the last tag with git-cliff, set up in
   `cliff.toml`.
4. Stages both packages on npm with provenance. A staged version is not public yet.
5. Creates a GitHub release with those notes.

Last, a maintainer approves both staged versions with 2FA, on npmjs.com or in the terminal.

```sh title="Terminal"
npm stage list @posuta/posuta
npm stage approve <stage-id>
```

<Callout type="info" title="Trusted publishing">
  The workflow logs in to npm through GitHub's OIDC, so there is no npm token to keep. Each
  package has a trusted publisher on npmjs.com for `alvgaona/posuta` and `release.yaml`, allowed
  to stage but not to publish.
</Callout>
