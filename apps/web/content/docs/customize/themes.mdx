You can change the poster's colours and fonts in three places: a line of frontmatter for one
poster, the theme file for a deeper change, or a theme package your whole lab shares.

## Where the look lives

The template's look is in `src/styles/theme.css`, a file in your project. It starts with
**tokens**: CSS custom properties (named values such as `--accent`) on `:root`, the top of the
page. The rest of the file uses only these names, so changing a token changes it everywhere.

There are two sets of values: light, and dark for screens set to dark mode. Print always uses the
light set.

| Token | What it is | Light | Dark |
| --- | --- | --- | --- |
| `--bg` | Page background | `#ffffff` | `#16181d` |
| `--surface` | Background of panels (`<Section panel>`) | `#f9f8f9` | `#1a1d23` |
| `--fg` | Main text | `#282a30` | `#edeef3` |
| `--fg-2` | Secondary text: lede, references | `#3c4149` | `#d0d4dc` |
| `--muted` | Captions, labels, footer | `#6f6e77` | `#9aa0ac` |
| `--border` | Lines and panel borders | `#e9e8ea` | `#2d3139` |
| `--accent` | Links, the title highlight, section numbers | `#1348dc` | `#6b96ff` |
| `--accent-tint` | A faint wash of the accent, for your own rules | 8% accent | 12% accent |
| `--fault` | A second colour (amber), for your own rules | `#d97706` | `#c97f2e` |
| `--font-display` | Title and headings | IBM Plex Serif | |
| `--font-body` | Body text | IBM Plex Sans | |
| `--font-mono` | Numbers, labels, code | IBM Plex Mono | |
| `--radius` | Corner rounding | `.4rem` | |
| `--posuta-gap` | Space between columns in `Row` and `Grid` | `2.1rem` | |

`--posuta-gap` is the one token posuta itself reads; the rest belong to the template. Add your
own tokens freely.

## Change a few tokens in the frontmatter

For one poster, set `theme:` in the frontmatter with token names (the leading `--` is optional):

```yaml title="src/pages/index.mdx"
theme: { accent: "#0a7d55", font-display: "Georgia, serif" }
```

These values apply in both light and dark mode, and in print.

To fix the colour scheme instead of following the reader's setting:

```yaml title="src/pages/index.mdx"
theme: light   # always light on screen
theme: dark    # always dark
```

<Callout type="warn">
With the template's theme, `theme: dark` also applies in print, so the PDF has a dark
background. Use it only if that is what you want on paper.
</Callout>

`theme:` works because the template's layout passes it to `<Canvas>`. In your own layout, pass it
the same way: `<Canvas theme={frontmatter.theme}>`.

## Edit the theme file

For anything more, edit `src/styles/theme.css`. Change the token values at the top, or the rules
below them: heading sizes, the section style, the footer. Dark values are set twice, once for
readers whose system is in dark mode and once for `theme: dark`; change both.

Fonts load from `@fontsource` packages at the top of the file. To use another font, install its
package (for example `pnpm add @fontsource/inter`), import it there, and set `--font-body` or
`--font-display`.

## A theme package for your lab

A lab can publish its colours and fonts once and use them in every poster. The package holds one
CSS file of tokens:

```css title="theme.css"
:root {
  --accent: #8a1538;
  --font-display: "Source Serif 4", Georgia, serif;
}
@media screen and (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { --accent: #e0708f; }
}
```

The package's `package.json` points its main entry at that file. Each poster installs the
package and names it in `astro.config.mjs`:

```js title="astro.config.mjs"
export default defineConfig({
  integrations: [posuta({ theme: "@my-lab/posuta-theme" })], // [!code highlight]
});
```

posuta then loads that CSS on every page. Only `:root` and the dark-mode media query are needed;
no other selectors.

Write the tokens outside any `@layer`. A package token then also beats the template's dark
values, so give it its own dark value, as above, wherever the light one would not read well on a
dark background.

## Why your tokens win

The template's theme sits in a **cascade layer** named `posuta.theme`. A cascade layer is a
named group of CSS rules; rules outside any layer beat rules inside one, whatever order the files
load in. Frontmatter tokens and a lab package are written outside a layer, so they override the
template's values without `!important`. The full layer order is on
[CSS, Tailwind and hooks](/docs/customize/css#layer-order).
