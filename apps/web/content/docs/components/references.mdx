`<References />` marks where the list of cited papers goes. posuta numbers it, formats it and
links each entry to its citations in the text.

<ComponentPreview name="references" />

<Callout>
On a poster you write `[@key]` in the text and `<References />` once, and posuta's citation plugin
replaces it with the list. The plugin does not run in these docs, so the examples build the list
from its parts, `References.Root` and `References.Item`, from the entries the plugin would put on
`frontmatter.references`. The Code tab shows what you write to lay the list out yourself.
</Callout>

## Usage

```mdx title="src/pages/index.mdx"
---
bibliography: refs.bib
---

A second-order system [@ogata2010modern].

<Section title="References">

<References />

</Section>
```

`<References />` renders `ol.posuta-refs`, one `li` per cited entry, in the order they are first
cited. The [Citations](/docs/writing/citations) guide covers the BibTeX file, numbering, styles
and the errors that stop the build.

## Examples

### Default items

The preview at the top is the same list as `<References />`, built from its parts, by mapping
`frontmatter.references` to `References.Item`s inside `References.Root`. Without children each
item shows the formatted reference, with URLs in it and its DOI as links.

### Your own entry content

Children of `References.Item` replace its content. The item keeps its `id`, so the numbers in the
text still link to it. Here the DOI link reads "DOI".

<ComponentPreview name="references-children" />

### Another list element

`as` on `References.Root` renders another element. A `ul` with the number written in each item
gives `[1]`-style labels, and the `refs` class removes the bullets in your CSS.

## API reference

### `References`

`<References />` is not a component. The citation plugin replaces it with the list at build time.
It takes no props. A page that cites with `[@key]` must have it, or the parts below, or the build
stops.

### `References.Root`

The list element. Import it as `import References from "@posuta/posuta/References"`, or use it in MDX
without an import.

### `References.Item`

One entry. Without children it shows the formatted reference, URLs in it as links, then
`doi:<doi>` linked to `https://doi.org/<doi>` when the entry has a DOI. With children, they
replace that content.

### Entries

posuta puts the entries cited on the page on `frontmatter.references`, in citation order.

### Markup and class hooks

```html
<!-- <References /> -->
<ol class="posuta-refs">
  <li id="ref-bostock2011d3">Bostock M, … 2011;17(12):2301–9. <a href="https://doi.org/10.1109/TVCG.2011.185">doi:10.1109/TVCG.2011.185</a></li>
</ol>

<!-- References.Root and References.Item -->
<ol class="posuta-refs">
  <li id="ref-bostock2011d3" class="posuta-ref">Bostock M, … <a href="https://doi.org/…">doi:…</a></li>
</ol>

<!-- a citation in the text -->
<span class="posuta-cite">[<a href="#ref-bostock2011d3">1</a>]</span>
```

| Hook | What it is |
| --- | --- |
| `.posuta-refs` | The list. |
| `.posuta-ref` | Each item built with `References.Item`. Items from `<References />` have no class, so select them with `.posuta-refs > li`. |
| `#ref-<key>` | Each entry, the target of the numbers in the text. |
| `.posuta-cite` | Each citation in the text, brackets included. |

posuta adds no CSS for the list. Numbering, spacing and link colour come from your theme.
